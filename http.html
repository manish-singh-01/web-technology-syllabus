TOPIC 04

HTTP

HTTP stands for HyperText Transfer Protocol. It is an application-layer protocol used for communication between web clients and servers.

01 • INTRODUCTION

What is HTTP?

HTTP defines how a client, such as a web browser, sends requests to a web server and how the server returns responses. It is a stateless protocol: each request is independent unless additional mechanisms maintain session information.

02 • WORKING

How HTTP Works

Browser→ HTTP Request→ Web Server→ HTTP Response
  • The browser sends an HTTP request.
  • The server processes the request.
  • The server returns a status code, headers and possibly a response body.
  • The browser processes and displays the response when appropriate.

03 • HTTP METHODS

Common HTTP Methods

  • GET: Retrieves a resource.
  • POST: Sends data for processing or resource creation.
  • PUT: Creates or replaces a resource at a specified URI.
  • DELETE: Requests deletion of a resource.
  • PATCH: Applies a partial modification to a resource.

04 • STATUS CODES

HTTP Status Codes

  • 200 OK: Request succeeded.
  • 301 Moved Permanently: Resource has a new permanent URL.
  • 400 Bad Request: Server cannot process the request due to a client error.
  • 404 Not Found: Requested resource was not found.
  • 500 Internal Server Error: Unexpected server-side error.

05 • HTTP VS HTTPS

Difference Between HTTP and HTTPS

  • HTTP: Does not itself provide transport encryption.
  • HTTPS: Uses TLS to protect data in transit and authenticate the server.
  • HTTPS is recommended for websites, especially when transmitting sensitive information.

06 • EXAM PREPARATION

Important Questions with Answers

1. Define HTTP.

HTTP is an application-layer protocol that defines request and response communication between web clients and servers.

2. Why is HTTP called stateless?

HTTP does not automatically remember the state of previous requests. Cookies, sessions and tokens can be used to maintain application state.

3. Differentiate HTTP and HTTPS.

HTTPS protects HTTP communication using TLS, providing encryption, integrity protection and server authentication. Plain HTTP does not provide these protections by itself.

4. Explain HTTP request and response.

A request contains a method, target and headers, and may contain a body. The response contains a status code, headers and may contain a body.
