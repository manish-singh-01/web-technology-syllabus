CORBA

Unit 3 – Web Services, AJAX and CORBA

1. Introduction to CORBA

CORBA stands for Common Object Request Broker Architecture. It is a standard developed by the Object Management Group (OMG) to enable communication between software objects running on different platforms and programming languages.

CORBA allows applications written in different programming languages to communicate with each other through a common interface. It hides the complexity of network communication from the application developer.

2. Objectives of CORBA

  • To support communication between distributed objects.
  • To provide platform independence.
  • To support different programming languages.
  • To simplify communication between applications.
  • To provide a standard architecture for distributed systems.
  • To hide the complexity of remote object communication.

3. Important Components of CORBA

1. Object Request Broker (ORB)

ORB is the main component of CORBA. It manages communication between client and server objects and helps clients access remote objects.

2. IDL (Interface Definition Language)

IDL defines the interfaces of objects. It describes the operations and data types that can be accessed by clients. It is independent of any specific programming language.

3. Client Stub

A client stub acts as a local representative of a remote object. It sends client requests to the ORB.

4. Server Skeleton

A server skeleton receives requests from the ORB and passes them to the actual server object for processing.

5. Object Adapter

The Object Adapter connects the ORB with the implementation of server objects and manages object references and requests.

6. GIOP and IIOP

GIOP (General Inter-ORB Protocol) defines how ORBs communicate. IIOP (Internet Inter-ORB Protocol) is a version of GIOP that works over TCP/IP networks.

4. Architecture of CORBA

CORBA architecture allows a client application to access remote objects through the Object Request Broker (ORB).

The ORB manages communication between the client and server. The client does not need to know the internal implementation or location of the remote object.

5. Working of CORBA

The working of CORBA involves the following steps:

  1. Interface Definition: The developer defines the remote object's interface using IDL.
  2. Code Generation: IDL compilers generate client stubs and server skeletons for supported programming languages.
  3. Client Request: The client calls a method through the client stub.
  4. ORB Communication: The ORB transfers the request to the appropriate server object.
  5. Server Processing: The server skeleton passes the request to the server object.
  6. Response: The result is returned to the client through the ORB.

6. Features of CORBA

  • Language Independence: Supports applications written in different programming languages.
  • Platform Independence: Supports communication across different operating systems and hardware platforms.
  • Location Transparency: Clients can access remote objects without managing their physical location.
  • Object-Oriented: Uses objects and interfaces for communication.
  • Distributed Communication: Enables objects on different computers to interact.
  • Interoperability: Provides standard protocols for communication between ORBs.

7. Advantages of CORBA

  • Supports communication between different programming languages.
  • Provides platform-independent communication.
  • Supports distributed application development.
  • Hides complex network communication details.
  • Promotes software reusability.
  • Provides a standard architecture for object communication.

8. Disadvantages of CORBA

  • Its architecture can be complex to understand and implement.
  • Configuration and maintenance may require specialized knowledge.
  • Communication overhead can affect performance.
  • Different implementations may create interoperability challenges.
  • It can be difficult to integrate with some modern web technologies.

9. Applications of CORBA

  • Banking Systems: Communication between distributed banking applications.
  • Telecommunication: Communication between network management systems.
  • Airline Systems: Interaction between reservation and booking applications.
  • Enterprise Applications: Communication between different business systems.
  • Industrial Systems: Interaction between distributed control applications.

10. CORBA vs Web Services

CORBA Web Services
Based on distributed object architecture. Based on service-oriented communication.
Uses ORB for communication. Uses web protocols such as HTTP/HTTPS.
Uses IDL to define interfaces. May use WSDL to describe SOAP services.
Commonly uses IIOP for ORB communication. May use SOAP or REST-based communication.
Often used in distributed enterprise systems. Widely used in web and application integration.

11. Difference Between CORBA and RMI

CORBA Java RMI
Language-independent architecture. Primarily designed for Java applications.
Uses IDL. Uses Java interfaces.
Uses ORB for communication. Uses Java Remote Method Invocation mechanisms.
Supports different programming languages. Primarily supports communication between Java objects.

Important Points for Exams

  • CORBA stands for Common Object Request Broker Architecture.
  • CORBA was developed by OMG.
  • ORB stands for Object Request Broker.
  • IDL stands for Interface Definition Language.
  • GIOP stands for General Inter-ORB Protocol.
  • IIOP stands for Internet Inter-ORB Protocol.
  • Client Stub represents a remote object on the client side.
  • Server Skeleton handles incoming requests on the server side.
  • CORBA supports language and platform independence.
