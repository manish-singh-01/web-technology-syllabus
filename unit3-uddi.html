Universal Description, Discovery and Integration

1. Introduction to UDDI

UDDI stands for Universal Description, Discovery and Integration. It is a standard for publishing and discovering information about web services.

UDDI provides a registry where organizations can publish information about their web services. Other applications or developers can search this registry to discover available services.

Important Points

  • UDDI is used for discovering web services.
  • It provides a registry for service information.
  • Service providers can publish their services.
  • Service users can search for required services.
  • It is associated with XML, SOAP and WSDL technologies.

2. Definition of UDDI

UDDI is an XML-based standard that defines a framework for describing, publishing and discovering web services.

It acts like a directory of web services in which service providers publish their service information and service requesters search for suitable services.

Simple Example

Suppose a company provides an online payment web service. It can publish information about that service in a UDDI registry. An e-commerce developer can search the registry to find the payment service.

3. Main Purpose of UDDI

  • Publishing: Allows providers to publish service details.
  • Discovery: Helps users find available web services.
  • Description: Stores information about organizations and services.
  • Integration: Helps applications locate services for integration.
  • Standardization: Provides a common structure for service information.

4. UDDI Architecture

UDDI architecture involves three main participants: service provider, service registry and service requester.

1. Service Provider

A service provider is an organization or developer that creates and publishes a web service.

2. Service Registry

A service registry stores information about published web services. UDDI provides the standard structure for this registry.

3. Service Requester

A service requester is an application or user that searches for and uses a web service.

5. Working of UDDI

UDDI follows a publish, find and bind process for web service discovery and use.

Step 1: Publish

The service provider publishes information about its web service in the UDDI registry.

Step 2: Find

The service requester searches the registry to find a suitable web service.

Step 3: Obtain Description

The requester obtains the service description, commonly represented using WSDL in SOAP-based services.

Step 4: Bind

The requester uses the service description and endpoint information to communicate with the service provider.

6. UDDI Data Structures

UDDI uses four major data structures to organize information about web services.

1. businessEntity

Represents a business or service provider. It contains information such as the business name, description and contact details.

2. businessService

Describes a web service offered by a business. It groups information about a particular service.

3. bindingTemplate

Contains technical information required to access a particular service, including its access endpoint.

4. tModel

Represents a technical model or reference used to describe service specifications and technical requirements.

7. Categories of Information in UDDI

White Pages

White Pages contain basic business information such as organization name, address and contact details.

Yellow Pages

Yellow Pages classify businesses according to industry, product and service categories.

Green Pages

Green Pages contain technical information about services, including access details and technical specifications.

8. Relationship Between UDDI, SOAP and WSDL

UDDI, SOAP and WSDL are commonly discussed together in traditional SOAP-based web service architecture.

  • UDDI: Helps publish and discover web services.
  • WSDL: Describes the service interface and operations.
  • SOAP: Provides the messaging format for communication.

9. Advantages of UDDI

  • Provides a standard service discovery mechanism.
  • Helps service providers publish service details.
  • Allows requesters to search for services.
  • Organizes business and technical information.
  • Supports integration between different applications.
  • Promotes service reuse.

10. Limitations of UDDI

  • Setting up and maintaining registries can be complex.
  • Published service information must remain accurate.
  • Finding a service does not guarantee its availability.
  • Security and access control need proper implementation.
  • Public UDDI registries did not achieve widespread adoption.

11. Applications of UDDI

  • Discovering payment services.
  • Finding business partner services.
  • Locating online booking services.
  • Discovering enterprise web services.
  • Organizing service information in private registries.
  • Supporting application integration.
