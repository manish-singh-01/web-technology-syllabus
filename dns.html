DNS

TOPIC 09

Domain Name System

Understand how DNS translates human-readable domain names into IP addresses so that browsers can locate websites on the Internet.

01 • INTRODUCTION

What is DNS?

DNS stands for Domain Name System. It is a hierarchical and distributed naming system that translates domain names into IP addresses and provides other information about domain names.

Humans find names such as www.example.com easier to remember than numerical IP addresses. DNS helps computers locate the correct server using a domain name.

Important Points

  • Full form: Domain Name System.
  • DNS is often called the phonebook of the Internet.
  • It helps resolve domain names to IP addresses.
  • DNS is hierarchical and distributed.
  • It can also store mail-server and other records.

02 • PURPOSE

Why Do We Need DNS?

Computers communicate over networks using IP addresses. Remembering the addresses of every website would be difficult for users. DNS makes Internet access easier by allowing people to use domain names.

  • Makes websites easier to access.
  • Maps domain names to IP addresses.
  • Allows server addresses to change without requiring users to remember new IP addresses.
  • Supports email routing through mail-related records.
  • Uses caching to reduce repeated lookups.

03 • WORKING

How Does DNS Work?

When a user enters a domain name into a browser, the computer checks available cached information. If it does not have the answer, a DNS resolver finds the required record.

1. The user enters www.example.com in a browser.

2. The device checks its DNS cache.

3. A DNS resolver searches for the required record if needed.

4. The resolver may query a root DNS server.

5. The resolver may query the appropriate top-level domain (TLD) server.

6. The authoritative DNS server provides the requested record.

7. The resolver returns the answer to the device.

8. The browser connects to the server using the resulting IP address.

Example

When you enter www.example.com, DNS can return an IP address associated with that name. The browser then uses the address to connect to the website's server.

04 • DNS HIERARCHY

DNS Hierarchy

DNS is organized into a hierarchy. Different servers are responsible for different parts of the domain name system.

1. Root DNS Servers
Direct resolvers toward the relevant top-level domain servers.

2. TLD DNS Servers
Handle extensions such as .com, .org, and .in.

3. Authoritative DNS Servers
Provide the DNS records for the domains they manage.

4. Recursive Resolver
Finds answers on behalf of the user's device and may cache them.

05 • DOMAIN STRUCTURE

Structure of a Domain Name

Consider the example:

www.example.com
  • www: A subdomain or host label.
  • example: The registered domain label in this example.
  • .com: The top-level domain (TLD).

Domain names are read from right to left when considering their hierarchy, with the root at the top.

06 • DNS RECORDS

Types of DNS Records

A Record

Maps a hostname to an IPv4 address.

Example: example.com → IPv4 address

AAAA Record

Maps a hostname to an IPv6 address.

CNAME Record

Creates an alias from one domain name to another domain name.

MX Record

Identifies mail servers responsible for receiving email for a domain.

NS Record

Identifies the name servers for a DNS zone.

TXT Record

Stores text information, often used for domain verification and email security policies.

PTR Record

Used for reverse DNS lookups, mapping an IP address to a domain name.

07 • PORTS

DNS Port Numbers

  • Port 53 UDP: Commonly used for DNS queries and responses.
  • Port 53 TCP: Used for DNS operations that require TCP, including zone transfers and some large responses.

DNS commonly uses UDP for ordinary queries, but TCP is also an important part of DNS operation.

08 • ADVANTAGES

Advantages of DNS

  • Users can remember domain names instead of IP addresses.
  • DNS caching can make repeated lookups faster.
  • Changes to server addresses can be managed through DNS records.
  • Supports email routing and other network services.
  • Its distributed design supports a very large number of domains.

09 • LIMITATIONS

Limitations and Security Issues

  • DNS failures can make websites difficult to reach by name.
  • Incorrect records can direct users to the wrong server.
  • DNS spoofing or cache poisoning can create security risks.
  • Changes may take time to appear because of caching and TTL values.

DNSSEC can help protect DNS data integrity and authenticity, but it does not encrypt ordinary DNS queries by itself.
