WSDL (Web Services Description Language)

Unit 3 – Web Services, AJAX and CORBA

1. Introduction to WSDL

WSDL stands for Web Services Description Language. It is an XML-based language used to describe the functionality and communication details of a web service.

WSDL tells a client what operations a web service provides, what input and output messages it uses, and how and where the service can be accessed.

It acts like a contract between a web service provider and a service consumer.

2. Purpose of WSDL

  • To describe the operations provided by a web service.
  • To define the input and output messages.
  • To specify the data types used by the service.
  • To describe the communication protocol and message format.
  • To provide the service endpoint address.
  • To help client applications communicate with web services.

3. Features of WSDL

  • XML-Based: WSDL documents are written in XML.
  • Platform Independent: It can describe services used by different platforms.
  • Language Independent: It is not restricted to a particular programming language.
  • Standard Format: It provides a structured description of web services.
  • Service Description: It describes available operations and messages.
  • Communication Details: It specifies bindings and service endpoints.

4. Structure of a WSDL Document

A WSDL document contains different elements that describe the interface and access details of a web service.

Main Elements of WSDL

  • Definitions: The root element of a WSDL document. It contains the service description and related declarations.
  • Types: Defines the data types used in messages, commonly through XML Schema.
  • Message: Describes the data exchanged between the client and the service.
  • PortType: Defines the abstract operations offered by the web service.
  • Binding: Specifies the concrete protocol and message format used for communication.
  • Service: Groups related endpoints through which the service can be accessed.
  • Port: Defines an endpoint by combining a binding with a network address.

5. Example of a WSDL Document

The following simplified WSDL 1.1 example describes a calculator service that provides an operation to add two numbers. 

<?xml version="1.0"?>

<definitions
    name="CalculatorService"
    targetNamespace="http://example.com/calculator"
    xmlns="http://schemas.xmlsoap.org/wsdl/"
    xmlns:tns="http://example.com/calculator"
    xmlns:xsd="http://www.w3.org/2001/XMLSchema"
    xmlns:soap="http://schemas.xmlsoap.org/wsdl/soap/">

    <types>
        <xsd:schema
            targetNamespace="http://example.com/calculator">

            <xsd:element name="AddRequest">
                <xsd:complexType>
                    <xsd:sequence>
                        <xsd:element name="a" type="xsd:int"/>
                        <xsd:element name="b" type="xsd:int"/>
                    </xsd:sequence>
                </xsd:complexType>
            </xsd:element>

            <xsd:element name="AddResponse">
                <xsd:complexType>
                    <xsd:sequence>
                        <xsd:element name="result" type="xsd:int"/>
                    </xsd:sequence>
                </xsd:complexType>
            </xsd:element>

        </xsd:schema>
    </types>

    <message name="AddInput">
        <part name="parameters" element="tns:AddRequest"/>
    </message>

    <message name="AddOutput">
        <part name="parameters" element="tns:AddResponse"/>
    </message>

    <portType name="CalculatorPortType">
        <operation name="Add">
            <input message="tns:AddInput"/>
            <output message="tns:AddOutput"/>
        </operation>
    </portType>

    <binding name="CalculatorBinding"
             type="tns:CalculatorPortType">
        <soap:binding
            style="document"
            transport="http://schemas.xmlsoap.org/soap/http"/>

        <operation name="Add">
            <soap:operation soapAction="Add"/>
            <input>
                <soap:body use="literal"/>
            </input>
            <output>
                <soap:body use="literal"/>
            </output>
        </operation>
    </binding>

    <service name="CalculatorService">
        <port name="CalculatorPort"
              binding="tns:CalculatorBinding">
            <soap:address
                location="http://example.com/calculator"/>
        </port>
    </service>

</definitions>

In this example, the CalculatorService provides an Add operation. The client sends two integer values, and the service returns their sum.

6. Working of WSDL

WSDL helps a client understand and use a web service.

  1. The service provider creates and publishes a WSDL document.
  2. The client obtains the WSDL document.
  3. The client reads the available operations and data types.
  4. The client identifies the required endpoint and communication binding.
  5. The client sends a request using the described message format.
  6. The web service processes the request and returns a response.

7. WSDL and SOAP Relationship

WSDL and SOAP are commonly used together in SOAP-based web services.

  • WSDL: Describes what the service does and how to access it.
  • SOAP: Provides the message format and rules for exchanging information.

8. Types of WSDL Operations

WSDL 1.1 defines four common operation message patterns:

  • One-Way: The client sends a message and does not receive a response message.
  • Request-Response: The client sends a request and receives a response.
  • Solicit-Response: The service sends a message and receives a response.
  • Notification: The service sends a message without expecting a response message.

9. Advantages of WSDL

  • Provides a standard description of web services.
  • Supports platform and language independence.
  • Clearly defines operations and message formats.
  • Helps developers create client applications.
  • Supports automated client code generation through development tools.
  • Works well with SOAP-based web services.

10. Disadvantages of WSDL

  • XML documents can become lengthy and complex.
  • Understanding large WSDL files can be difficult for beginners.
  • Changes to service definitions may require client updates.
  • It is often associated with more complex SOAP-based service setups.
  • It does not itself execute or provide the web service.

11. Difference Between WSDL, SOAP and UDDI

WSDL SOAP UDDI
Describes a web service. Exchanges structured messages. Helps publish and discover services.
XML-based description language. XML-based messaging protocol. Registry standard.
Defines operations and endpoints. Defines message structure. Stores service information.
Tells how to access a service. Carries request and response data. Helps users find services.

12. Applications of WSDL

  • Banking and financial web services.
  • Enterprise application integration.
  • Online payment systems.
  • Travel and booking services.
  • Business-to-business communication.
  • Distributed software applications.

Important Points for Exams

  • WSDL stands for Web Services Description Language.
  • It is an XML-based language.
  • It describes the functionality and access details of a web service.
  • Types defines data types.
  • Message describes exchanged data.
  • PortType defines abstract operations.
  • Binding specifies communication protocol and message format.
  • Service and Port describe service endpoints.
