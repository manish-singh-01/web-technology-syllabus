Web Services

Unit 3 – Web Services, AJAX and CORBA

1. Introduction to Web Services

A Web Service is a software system that allows different applications to communicate and exchange data over a network. It provides a standard way for applications to interact with each other, even when they are developed using different programming languages or platforms.

Web services are commonly used to connect websites, mobile applications, databases and enterprise software systems.

For example, a shopping website may use a payment web service to process online payments.

2. Definition of Web Services

A web service is a network-accessible software component that performs a specific task and allows other applications to access its functionality through standard communication protocols and data formats.

3. Characteristics of Web Services

  • Interoperability: Different applications can communicate with each other.
  • Platform Independent: Web services can work across different operating systems.
  • Language Independent: They can connect applications written in different programming languages.
  • Reusability: A service can be used by multiple applications.
  • Standard Communication: They use common web protocols and data formats.
  • Loose Coupling: The client and service are connected through a defined interface rather than depending on each other's internal implementation.
  • Discoverability: Services can be described and, in some systems, discovered through registries.

Working Steps

  1. The client sends a request to the web service.
  2. The web service receives the request.
  3. The service processes the requested operation.
  4. It may retrieve or update information in a database.
  5. The service prepares a response.
  6. The response is returned to the client.

5. Components and Technologies of Web Services

1. XML (Extensible Markup Language)

XML is used to represent and exchange structured data. It is commonly used in SOAP-based web services.

2. SOAP (Simple Object Access Protocol)

SOAP is an XML-based messaging protocol used to exchange structured information between applications.

3. WSDL (Web Services Description Language)

WSDL describes the operations, messages, bindings and endpoints of a web service.

4. UDDI (Universal Description, Discovery and Integration)

UDDI is a registry standard that helps publish and discover web services.

5. HTTP and HTTPS

HTTP and HTTPS are commonly used to transfer web service requests and responses over a network.

6. Types of Web Services

1. SOAP Web Services

SOAP web services use the SOAP messaging protocol. They commonly exchange XML-based messages and can use WSDL to describe their interfaces.

2. RESTful Web Services

RESTful web services follow the REST architectural style. They commonly use HTTP methods such as GET, POST, PUT and DELETE to work with resources.

REST APIs frequently use JSON for data exchange, although other formats can also be used.

8. Web Service Request and Response Example

The following is a simplified REST API example that retrieves information about a user.

Request

GET /api/users/101 HTTP/1.1
Host: example.com
Accept: application/json

Response

{
    "id": 101,
    "name": "Rahul",
    "course": "B.Tech",
    "department": "Computer Science"
}

Here, the client requests user information using an HTTP GET request. The service returns the data in JSON format.

9. Advantages of Web Services

  • Allow communication between different applications.
  • Support platform and programming language independence.
  • Promote software reusability.
  • Reduce integration difficulties between systems.
  • Support distributed application development.
  • Can be accessed over networks and the internet.
  • Help organizations connect different software systems.

10. Disadvantages of Web Services

  • Depend on network availability and connectivity.
  • May introduce communication delays.
  • Require security measures to protect data.
  • Integration and configuration can be complex.
  • Service failures can affect dependent applications.
  • Large messages and frequent requests may increase resource usage.

11. Applications of Web Services

  • Banking: Online transactions and account services.
  • E-Commerce: Payment gateways and order processing.
  • Travel: Flight booking and hotel reservation systems.
  • Weather: Weather information and forecasts.
  • Healthcare: Sharing information between healthcare systems.
  • Education: Student portals and online learning systems.
  • Social Media: Sharing data between applications through APIs.

Important Points for Exams

  • A web service allows applications to communicate over a network.
  • Web services support interoperability.
  • They are generally platform and language independent.
  • SOAP and REST are common approaches for building web services.
  • WSDL describes SOAP-based service interfaces.
  • UDDI supports service publishing and discovery.
  • Web services commonly use HTTP or HTTPS.
