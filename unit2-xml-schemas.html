XML Schemas

Unit 2 | Topic 08

Learn how XML Schemas define the structure and rules of XML documents.

1. Introduction to XML

XML stands for Extensible Markup Language. It is a markup language designed to store, organize and transport data. XML allows users to create their own tags according to their requirements.

Important Points

  • XML stands for Extensible Markup Language.
  • It is used to store and transport structured data.
  • XML tags are user-defined.
  • XML is both human-readable and machine-readable.
  • XML is case-sensitive.
  • XML documents must follow proper syntax rules.

2. What is an XML Schema?

An XML Schema defines the structure, elements, attributes and data types allowed in an XML document. It specifies the rules that an XML document must follow.

XML Schema is commonly written using XML Schema Definition (XSD).

Purpose of XML Schema

  • Defines valid elements and attributes.
  • Specifies the data types of elements.
  • Defines the order of elements.
  • Specifies minimum and maximum occurrences.
  • Helps validate XML documents.

3. Introduction to XSD

XSD stands for XML Schema Definition. It is a language used to describe the structure and rules of an XML document.

Basic XSD Structure

<xs:schema
    xmlns:xs="http://www.w3.org/2001/XMLSchema">

    <xs:element name="student"
                type="xs:string"/>

</xs:schema>

The XML Schema namespace identifies the XML Schema vocabulary. The prefix xs is commonly used for XML Schema elements and data types.

4. XML Schema Elements

Elements represent the data items in an XML document. The xs:element declaration defines an element and optionally specifies its data type.

Example

<xs:element name="name" type="xs:string"/>

<xs:element name="age" type="xs:integer"/>

<xs:element name="price" type="xs:decimal"/>

5. XML Schema Data Types

XML Schema provides built-in data types to specify the kind of values that an XML element or attribute can contain.

Common Built-in Data Types

  • xs:string: Stores text values.
  • xs:integer: Stores whole numbers.
  • xs:decimal: Stores decimal numbers.
  • xs:boolean: Stores true or false values.
  • xs:date: Stores date values.
  • xs:time: Stores time values.
  • xs:float: Stores floating-point values.
  • xs:double: Stores double-precision values.
  • xs:anyURI: Stores URI values.

Example

<xs:element name="studentName"
            type="xs:string"/>

<xs:element name="rollNumber"
            type="xs:integer"/>

<xs:element name="marks"
            type="xs:decimal"/>

<xs:element name="isActive"
            type="xs:boolean"/>

6. Simple Types

A simple type contains only text values. It cannot contain child elements or attributes.

Example

<xs:element name="age" type="xs:integer"/>

In this example, the age element can contain an integer value.

7. Complex Types

A complex type is used when an XML element contains child elements, attributes or both.

Example

<xs:element name="student">
    <xs:complexType>
        <xs:sequence>
            <xs:element name="name" type="xs:string"/>
            <xs:element name="age" type="xs:integer"/>
            <xs:element name="course" type="xs:string"/>
        </xs:sequence>
    </xs:complexType>
</xs:element>

8. XML Schema Attributes

Attributes provide additional information about XML elements. The xs:attribute declaration defines an attribute in an XML Schema.

Example

<xs:element name="student">
    <xs:complexType>
        <xs:attribute name="id"
                      type="xs:integer"
                      use="required"/>
    </xs:complexType>
</xs:element>

The use attribute can specify whether an attribute is required, optional or prohibited.

9. XML Schema Occurrence Indicators

Occurrence indicators define how many times an element can appear in an XML document.

  • minOccurs: Specifies the minimum number of occurrences.
  • maxOccurs: Specifies the maximum number of occurrences.

Example

<xs:element name="subject"
            type="xs:string"
            minOccurs="1"
            maxOccurs="5"/>

In this example, the subject element can appear at least once and at most five times.

10. XML Schema Indicators

Indicators are used to control the order and number of elements in an XML document.

A. Sequence Indicator

The xs:sequence indicator requires child elements to appear in the specified order. 

<xs:sequence>
    <xs:element name="name" type="xs:string"/>
    <xs:element name="age" type="xs:integer"/>
</xs:sequence>

B. Choice Indicator

The xs:choice indicator allows one element from a specified group to appear. 

<xs:choice>
    <xs:element name="email" type="xs:string"/>
    <xs:element name="phone" type="xs:string"/>
</xs:choice>

C. All Indicator

The xs:all indicator allows the specified child elements to appear in any order, subject to its occurrence rules. 

<xs:all>
    <xs:element name="name" type="xs:string"/>
    <xs:element name="age" type="xs:integer"/>
</xs:all>

11. XML Schema Restrictions

Restrictions are used to limit the values that an XML element or attribute can contain.

Common Restriction Facets

  • minInclusive: Defines a minimum allowed value.
  • maxInclusive: Defines a maximum allowed value.
  • minLength: Defines minimum text length.
  • maxLength: Defines maximum text length.
  • length: Defines an exact length.
  • enumeration: Allows only specified values.
  • pattern: Restricts values using a regular expression.

Example: Age Restriction

<xs:element name="age">
    <xs:simpleType>
        <xs:restriction base="xs:integer">
            <xs:minInclusive value="18"/>
            <xs:maxInclusive value="60"/>
        </xs:restriction>
    </xs:simpleType>
</xs:element>

12. XML Schema Validation

XML validation checks whether an XML document follows the structure and rules defined in its associated XML Schema.

Steps of Validation

  1. Create an XML document.
  2. Create an XSD schema file.
  3. Connect the XML document to the schema.
  4. Use an XML validator or parser.
  5. Check whether the XML document follows the schema rules.

Linking an XML Document with XSD

<student
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xsi:noNamespaceSchemaLocation="student.xsd">

    <name>Manish</name>
    <age>21</age>
    <course>CSE</course>

</student>

13. Complete XML Schema Example

The following example demonstrates an XML document and its corresponding XSD file.

XML File: student.xml

<student
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
    xsi:noNamespaceSchemaLocation="student.xsd">

    <name>Manish</name>
    <age>21</age>
    <course>Computer Science</course>

</student>

XSD File: student.xsd

<xs:schema
    xmlns:xs="http://www.w3.org/2001/XMLSchema">

    <xs:element name="student">
        <xs:complexType>
            <xs:sequence>
                <xs:element name="name" type="xs:string"/>
                <xs:element name="age" type="xs:integer"/>
                <xs:element name="course" type="xs:string"/>
            </xs:sequence>
        </xs:complexType>
    </xs:element>

</xs:schema>

14. Advantages of XML Schema

  • Defines the structure of XML documents.
  • Supports different data types.
  • Helps validate XML data.
  • Supports restrictions and occurrence rules.
  • Provides better control over XML document structure.
  • Supports namespaces.

15. Difference Between DTD and XML Schema

DTD XML Schema (XSD)
DTD stands for Document Type Definition. XSD stands for XML Schema Definition.
Uses its own non-XML syntax. Uses XML syntax.
Provides limited data types. Supports many built-in data types.
Has limited value restrictions. Supports detailed value restrictions.
Has limited namespace support. Supports XML namespaces.
