Web Services Architecture

Unit 3 – Web Services, AJAX and CORBA

1. Introduction to Web Services Architecture

Web Services Architecture is a framework that describes how different applications communicate and exchange information through web services over a network.

It defines the roles of service providers, service requesters and service registries, along with the operations used to publish, find and bind web services.

It helps applications developed using different programming languages and platforms communicate with each other.

2. Basic Components of Web Services Architecture

1. Service Provider

A service provider is an organization or application that creates and offers a web service to other applications.

Example: A company providing a payment gateway API.

2. Service Requester

A service requester is a client application that searches for and uses a web service.

Example: An online shopping application using a payment service.

3. Service Registry

A service registry is a directory where information about available web services can be published and discovered. UDDI is a standard associated with this registry model.

4. Three Main Operations of Web Services

1. Publish

The service provider publishes information about its web service in a service registry.

2. Find

The service requester searches the registry to find a suitable web service.

3. Bind

The requester uses the service description and endpoint information to connect to and invoke the selected service.

5. Technologies Used in Web Services Architecture

1. XML (Extensible Markup Language)

XML is used to represent structured data and is commonly used in SOAP-based web services.

2. SOAP (Simple Object Access Protocol)

SOAP is an XML-based messaging protocol used to exchange structured information between applications.

3. WSDL (Web Services Description Language)

WSDL describes the operations, messages, bindings and endpoints of a web service.

4. UDDI (Universal Description, Discovery and Integration)

UDDI is a registry standard used to publish and discover web services.

5. HTTP and HTTPS

HTTP and HTTPS are commonly used to transfer web service messages between clients and servers.

6. Working of Web Services Architecture

The working process generally follows these steps:

  1. The service provider develops and deploys a web service.
  2. The provider describes the service using a service description such as WSDL.
  3. The provider publishes service information in a registry when a registry is used.
  4. The service requester searches the registry to find the required service.
  5. The requester obtains the service description and endpoint details.
  6. The requester sends a request to the service.
  7. The service processes the request and sends back a response.

7. Role of SOAP, WSDL and UDDI

Technology Role
SOAP Provides a structured message format for communication.
WSDL Describes the web service and how to access it.
UDDI Helps publish and discover web services through a registry.
XML Represents structured data in XML-based messages.
HTTP/HTTPS Commonly transports requests and responses.

8. Types of Web Services Architecture

1. SOAP-Based Architecture

SOAP-based architecture uses SOAP messages for communication. WSDL commonly describes the service interface, while HTTP or other supported transport protocols carry messages.

2. REST-Based Architecture

REST-based architecture follows the REST architectural style. It uses resources identified by URLs and commonly uses HTTP methods such as GET, POST, PUT and DELETE.

REST APIs frequently exchange data in JSON format, although XML and other formats can also be used.

10. Advantages of Web Services Architecture

  • Supports communication between different applications.
  • Provides platform and language independence.
  • Promotes software reusability.
  • Supports distributed application development.
  • Allows services to be discovered and accessed through defined interfaces.
  • Helps integrate different business systems.
  • Can be extended according to application requirements.

11. Disadvantages of Web Services Architecture

  • Requires proper network connectivity.
  • Communication may introduce network delays.
  • Security must be carefully implemented.
  • Integration may become complex in large systems.
  • Service failures can affect dependent applications.
  • Managing multiple services requires monitoring and maintenance.

12. Applications of Web Services Architecture

  • Banking: Connecting banking applications and payment systems.
  • E-Commerce: Integrating shopping, payment and delivery services.
  • Healthcare: Sharing information between healthcare applications.
  • Travel: Connecting flight and hotel booking systems.
  • Education: Integrating student portals and learning platforms.
  • Business: Connecting enterprise applications and services.

Important Points for Exams

  • Web Services Architecture defines how applications communicate through web services.
  • It has three main roles: provider, requester and registry.
  • Publish, Find and Bind are its three important operations.
  • SOAP is used for structured message exchange.
  • WSDL describes the service interface.
  • UDDI supports service publishing and discovery.
  • REST is another common architectural style for web APIs.
