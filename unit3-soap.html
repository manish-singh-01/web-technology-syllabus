SOAP (Simple Object Access Protocol)

Unit 3 – Web Services, AJAX and CORBA

1. Introduction to SOAP

SOAP stands for Simple Object Access Protocol. It is an XML-based messaging protocol used for exchanging structured information between applications over a network.

SOAP allows applications developed using different programming languages and platforms to communicate with each other. It is commonly used with HTTP or HTTPS.

2. Purpose of SOAP

The main purpose of SOAP is to provide a standard method for communication between distributed applications.

  • To exchange data between different applications.
  • To support communication between different platforms.
  • To provide a standard XML-based message format.
  • To support distributed and web-based systems.
  • To enable communication between client and server applications.

3. Features of SOAP

  • XML-Based: SOAP messages are written in XML format.
  • Platform Independent: It works across different operating systems.
  • Language Independent: Applications written in different programming languages can communicate.
  • Extensible: Additional information can be included through SOAP headers.
  • Transport Independent: SOAP can work with different transport protocols.
  • Standardized: It follows defined messaging rules and structure.

4. SOAP Architecture

SOAP architecture describes how messages are exchanged between applications. It generally includes a sender, receiver and, when required, intermediaries.

  • SOAP Sender: Creates and sends the SOAP message.
  • SOAP Receiver: Receives and processes the message.
  • SOAP Intermediary: An optional system that processes or forwards a SOAP message.

5. Structure of a SOAP Message

A SOAP message is an XML document. Its main elements are Envelope, Header, Body and Fault.

Main Components

  • Envelope: The root element that identifies the XML document as a SOAP message. It is mandatory.
  • Header: An optional element containing additional information such as authentication or routing details.
  • Body: A mandatory element containing the actual request or response data.
  • Fault: An optional element inside the Body used to communicate errors.

SOAP Message Structure

<soap:Envelope>
    <soap:Header>
        Header Information
    </soap:Header>

    <soap:Body>
        Request or Response Data

        <soap:Fault>
            Error Information
        </soap:Fault>
    </soap:Body>
</soap:Envelope>

6. Example of a SOAP Message

The following example shows a SOAP request that asks a server to calculate the sum of two numbers.

SOAP Request

<?xml version="1.0"?>
<soap:Envelope
 xmlns:soap="http://www.w3.org/2003/05/soap-envelope">

    <soap:Header>
        <!-- Optional header information -->
    </soap:Header>

    <soap:Body>
        <AddNumbers xmlns="http://example.com/calculator">
            <number1>10</number1>
            <number2>20</number2>
        </AddNumbers>
    </soap:Body>

</soap:Envelope>

SOAP Response

<?xml version="1.0"?>
<soap:Envelope
 xmlns:soap="http://www.w3.org/2003/05/soap-envelope">

    <soap:Body>
        <AddNumbersResponse
         xmlns="http://example.com/calculator">
            <result>30</result>
        </AddNumbersResponse>
    </soap:Body>

</soap:Envelope>

In this example, the client sends two numbers (10 and 20). The server processes the request and returns the result (30).

7. Working of SOAP

SOAP communication generally follows these steps:

  1. The client creates a SOAP XML request.
  2. The request is sent to the web service.
  3. The server receives and processes the SOAP message.
  4. The server performs the requested operation.
  5. The server creates a SOAP response.
  6. The response is sent back to the client.
  7. The client reads and uses the response.

8. SOAP over HTTP

SOAP is commonly used with HTTP because HTTP is widely supported by web servers, browsers and network infrastructure.

  • The client generally sends a SOAP request using HTTP POST.
  • The message contains XML data.
  • The server processes the request.
  • The server returns a SOAP response.
  • HTTPS can be used to protect communication through encryption.

9. Advantages of SOAP

  • Platform and programming language independent.
  • Uses a standardized XML message format.
  • Supports communication over different transport protocols.
  • Supports extensions for security and reliability.
  • Suitable for enterprise-level applications.
  • Provides a structured way to handle errors using SOAP Fault.

10. Disadvantages of SOAP

  • XML messages can be lengthy.
  • Processing XML may require additional resources.
  • It can be more complex to implement than simpler APIs.
  • Messages may be slower or larger than lightweight alternatives.
  • Requires proper configuration and understanding of SOAP standards.

11. Difference Between SOAP and REST

SOAP REST
SOAP is a messaging protocol. REST is an architectural style.
Uses XML-based messages. Can use JSON, XML and other formats.
Defines a strict message structure. Uses resources and standard HTTP methods.
Can work over different transport protocols. Commonly uses HTTP/HTTPS.
Often used in enterprise systems. Commonly used in web and mobile APIs.

12. Applications of SOAP

  • Banking and financial applications.
  • Enterprise software systems.
  • Payment processing systems.
  • Business-to-business communication.
  • Travel and reservation systems.
  • Applications requiring standardized messaging.

13. SOAP vs Web Service

A web service is a software system that allows applications to communicate over a network. SOAP is one protocol that can be used to exchange messages in a web service.

Therefore, SOAP and web services are related, but they are not the same thing.

Important Points for Exams

  • SOAP stands for Simple Object Access Protocol.
  • SOAP is an XML-based messaging protocol.
  • SOAP messages use an Envelope as their root element.
  • Header is optional, while Envelope and Body are mandatory.
  • Fault is used for error information inside the Body.
  • SOAP is commonly used with HTTP and HTTPS.
  • SOAP supports platform and language independence.
